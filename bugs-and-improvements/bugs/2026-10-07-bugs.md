# Bug Audit

## Summary

This repository is an ARIA Lab Jekyll website, not a training or evaluation codebase. The audit covered site configuration, public pages, project cards, bibliography, deployment and test wiring, and all seven Research-page interactive demos. Four confirmed bugs were documented: **1 High remains open; 3 Medium were fixed on 2026-10-07**. The remaining risk is an invalid cross-paper speedup presented as an empirical result.

Static validation included JavaScript syntax checks for all seven demo scripts, existence checks for local Research-page images and demo includes, arithmetic checks against the local RELINK PDF, and a comparison with the local SSMP and ITSELF papers. Runtime observations and limits are recorded below.

## Bugs

### BUG-001: SSMP speedup compares different inference tasks and papers

**Status:** Open

**Severity:** High

**Confidence:** High

**Category:** Research claims / benchmark correctness

**Location:**

- `_pages/research.md`, lines 61–67
- `_includes/research-interactive-demos/ssmp_benchmark.html`, `BENCHMARK_CONFIG`, `updateWorkload`, lines 12–16, 37–44, 47–84, 123–150, 184–210

**Problem:** The demo labels a joint SSMP/ITSELF/branch-and-bound latency comparison “empirical” and derives an SSMP speedup above 273,000× from `2.703 / 0.00000987`. The 2.703-second branch-and-bound comparator belongs to the MPE comparison shown alongside ITSELF; SSMP addresses marginal MAP in probabilistic circuits. The widget presents these as though they were measured on one comparable workload.

**Why this is a bug:** The local AAAI SSMP paper (`assets/pdf/AAAI_arya_2024_networkapproximatorsa.pdf`, “Conclusion and Future Work”) reports approximately 7–10 microseconds for SSMP on an A40 GPU and approximately 7 milliseconds for its Max-approximation comparator, describing an almost 1,000× speedup. Its abstract and evaluation concern marginal MAP in probabilistic circuits. The local NeurIPS ITSELF paper (`assets/pdf/NeurIPS_12727_A_Neural_Network_Approac.pdf`) concerns arbitrary-evidence MPE in probabilistic models and compares against AOBB. A latency ratio across these tasks, models, and experimental settings is not a measured SSMP speedup.

**Expected behavior:** Associate each published latency and speedup with its own paper, task, baseline, and experimental conditions. Show a cross-paper illustration only if it is explicitly labeled as non-comparable and does not imply a measured speedup.

**Current behavior:** The static card, GIF caption, workload calculator, and Research-page prose state or imply the >273,000× SSMP result. The calculator extrapolates that ratio to 1,000–1,000,000 queries.

**Evidence:** `baselineLatency: 2.703`, `ssmpLatency: 0.00000987`, and `ssmpSpeedup = baselineLatency / ssmpLatency` appear in the include. The local SSMP paper instead names Max approximation at roughly 7 ms as its time comparator. Its task and ITSELF's task differ.

**Impact:** Visitors may interpret an unsupported cross-study ratio and workload totals as a published head-to-head benchmark. The error propagates across the card, animation caption, calculator, and publication summary.

**Suggested fix direction:** Trace each number to the corresponding paper and experiment. Separate the two benchmark contexts or restrict comparative claims to matched, published measurements. Reconcile the Research-page sentence, cards, GIF caption, and calculator together.

**Validation after fixing:** For every displayed latency, ratio, and workload result, record the source paper, task, comparator, hardware, and calculation. Check that no SSMP speedup uses an ITSELF/AOBB latency as its denominator. Open `/research/`, select every workload, and verify that prose and values agree with the cited source.

### BUG-002: RELINK Random win count is taken from the wrong contingency cell

**Status:** Fixed (2026-10-07)

**Severity:** Medium

**Confidence:** High

**Category:** Research claims / metric correctness

**Location:**

- `_includes/research-interactive-demos/relink_budget_explorer.html`, `viewData.random_fof`, lines 682–689

**Problem:** The Random/FoF view says RELINK beats Random in 462 of 480 settings but also labels Random as winning 20 of 480 against RELINK. The two counts sum to 482.

**Why this is a bug:** Pairwise wins in 480 configurations cannot total more than 480. Figure 3 in the local paper (`assets/pdf/RELINK_CIKM2025.pdf`) gives **18** for the Random row versus the RELINK column. The value **20** is the Degree row versus the Random column, a different comparison.

**Expected behavior:** The Random row should show the count from the Random-versus-RELINK cell, with its percentage calculated from the same 480 configurations.

**Current behavior when found:** Switching to “vs. Random & FoF” rendered `4.2% Win Rate (20 / 480 wins)` for Random while showing `462 / 480` for RELINK.

**Evidence:** The source's `all` and `random_fof` entries both give 462 RELINK wins over Random. The PDF's Figure 3 has 18 in the Random/RELINK cell and 20 in the Degree/Random cell.

**Impact:** The interactive chart displays an incorrect empirical count and percentage and contradicts its own headline.

**Suggested fix direction:** Map each displayed row to the correct Figure 3 cell and recompute the corresponding percentage; check other cells at the same time.

**Validation after fixing:** Open `/research/`, expand RELINK, select “vs. Random & FoF,” compare each displayed count with the row/column labels in Figure 3, and verify that reciprocal counts do not exceed 480.

**Resolution and verification:** Changed the Random row to `18 / 480` and `3.8%`, matching Figure 3. A fresh Docker Jekyll build succeeded; its rendered `/research/` HTML contains the corrected row. The focused arithmetic assertion `462 + 18 == 480` passed. Browser interaction was not exercised.

### BUG-003: Repositories page enables trophy images from a failing host

**Status:** Fixed (2026-10-07)

**Severity:** Medium

**Confidence:** High

**Category:** Configuration / external assets

**Location:**

- `_config.yml`, `repo_trophies`, lines 42–57
- `_pages/repositories.md`, trophy conditional, lines 22–35

**Problem:** `repo_trophies.enabled` is `true`, causing the repositories page to emit images from `github-profile-trophy.vercel.app`, although the configured instance responds with HTTP 402.

**Why this is a bug:** The comment immediately above the setting and `docs/CUSTOMIZE.md` state that this public instance is disabled. The visual test in `test/visual/interactions.spec.js` expects no trophy images for that reason. The page includes two GitHub users, so this path is reachable.

**Expected behavior:** Repositories should display working trophy images only when a functioning host is configured, or omit the broken cards.

**Current behavior when found:** The enabled conditional rendered trophy image URLs. The host returned HTTP 402 during this audit; browser `onerror` handlers then hid their cards, leaving a failed external request for each image.

**Evidence:** `_config.yml` sets `enabled: true`; `_pages/repositories.md` includes `repository/repo_trophies.liquid` under that flag; the existing rendered `_site/repositories/index.html` contains the trophy URLs. A direct request to [the configured host](https://github-profile-trophy.vercel.app/) returned HTTP 402 on 2026-10-07.

**Impact:** Broken external images and empty/vanishing cards on the repositories page; avoidable network requests and a failing visual assertion when that test is run against the site configuration.

**Suggested fix direction:** Reconcile the flag and host with the documented available service and the site's intended repositories-page behavior.

**Validation after fixing:** Build the site, inspect `/repositories/` for emitted trophy URLs, and load the page with network errors visible. If trophies remain enabled, verify every image request succeeds. Run the repositories visual interaction test using this site's actual configuration.

**Resolution and verification:** Set `repo_trophies.enabled: false`, consistent with the adjacent configuration comment and existing visual assertion. A fresh Docker Jekyll build succeeded; its rendered `/repositories/` HTML contains no `github-profile-trophy.vercel.app` URLs. Browser network behavior was not exercised.

### BUG-004: Public CV route publishes the starter's Einstein résumé

**Status:** Fixed (2026-10-07)

**Severity:** Medium

**Confidence:** High

**Category:** Content / configuration

**Location:**

- `_pages/cv.md`, lines 1–9
- `_config.yml`, `jekyll_get_json`, lines 702–704
- `assets/json/resume.json`, `basics` and subsequent sections
- `assets/pdf/example_pdf.pdf`

**Problem:** The public `/cv/` route is configured to render `assets/json/resume.json`, which is the starter's Albert Einstein sample résumé, and offers a one-page `example_pdf.pdf` whose text is “A pdf hosted as part of the website.”

**Why this is a bug:** A lab site publicly serving a CV page should not identify its subject as Albert Einstein or offer a placeholder download. `nav: false` removes it from the menu but does not prevent direct access or sitemap indexing.

**Expected behavior:** The route should show accurate site-owned CV content and a corresponding real PDF if a CV is offered.

**Current behavior when found:** The generated CV HTML identified “Albert Einstein”; the generated sitemap included `https://aria-research-lab.github.io/cv/`.

**Evidence:** `_config.yml` loads `assets/json/resume.json`; that JSON begins with `basics.name: Albert Einstein`. `pdftotext assets/pdf/example_pdf.pdf -` yields placeholder text. The existing `_site/cv/index.html` contains “Albert Einstein” and `_site/sitemap.xml` lists `/cv/` (those generated files predate this audit and are corroborating evidence, not proof of a fresh build).

**Impact:** Direct visitors and search crawlers can see incorrect identity information and a non-CV download.

**Suggested fix direction:** Decide whether the lab site should expose a CV route; then align the route, JSON source, PDF link, and sitemap behavior with accurate content.

**Validation after fixing:** Build the site and visit `/cv/`; confirm the page and download identify the intended person or that the route is unavailable and absent from the sitemap if intentionally removed. Check search results after deployment as appropriate.

**Resolution and verification:** Changed `/cv/` to a plain page linking to Dr. Arya's verified [personal-site CV PDF](https://shivvrat.github.io/cv/CV_Shivvrat_Arya.pdf). A fresh Docker Jekyll build succeeded; its rendered `/cv/` HTML contains the real PDF link and no “Albert Einstein” text. The sample JSON and PDF remain in the starter assets but are no longer used by this page. Browser navigation was not exercised.

## Runtime Validation

- Ran `node --check --input-type=commonjs` on the inline JavaScript extracted from all seven Research demo includes: all seven passed syntax checking.
- Checked local `/assets/...` references and all `research-interactive-demos/...` includes in 38 content files: no missing local Research assets or demo includes were found. Generic gem-owned includes were outside this local-file check.
- Used `pdftotext -layout` on the local SSMP, ITSELF, DDN, and RELINK papers. The RELINK contingency cell and the SSMP comparator were verified from the PDFs. The DDN Table 1 and Table 2 values checked against the demo agreed with the source.
- Checked `pdftotext assets/pdf/example_pdf.pdf -`, `assets/json/resume.json`, and the existing generated CV page/sitemap. The generated `_site` files were older than the latest Research changes and were not treated as fresh runtime proof.
- The configured trophy host returned HTTP 402 during the audit.
- After fixing BUG-002 through BUG-004, focused static assertions passed for the corrected RELINK value, disabled trophy setting, and CV-page link. `node --check` passed for the changed RELINK script. `docker compose run --rm jekyll bundle exec jekyll build --destination /tmp/_site` completed successfully. A second container build checked its rendered `/research/`, `/repositories/`, and `/cv/` HTML: corrected Random row present, trophy host absent, real CV link present, and Einstein absent.
- `bundle check` could not use the host Ruby because the locked Bundler 4.0.6 is unavailable there. `npm run lint:prettier` reports 14 files with formatting warnings that predate these fixes; the Jekyll build and focused assertions passed. The audit did not include a browser interaction run.

- The TIIS Video-LLaVA view has eight data rows and eight DOM row slots. An earlier nine-row suspicion was a misread; `applyEvaluationView` can render the current data.

- All seven interactive demo scripts pass JavaScript syntax checking; this does not establish browser behavior.
